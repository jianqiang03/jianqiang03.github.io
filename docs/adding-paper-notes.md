# 如何新增一篇论文解读：从论文链接到网站发布

这份指南针对「观行」当前的静态网站。最方便的方式是把论文链接和关注重点交给 AI，明确要求它完成深读、页面制作、首页接入、检查和发布。也可以按下面的步骤手动完成。

**当前没有自动文章管理后台，也没有“放入 Markdown 就自动发布”的生成器。** 新增文章需要创建 HTML 页面，并修改首页入口；`git push` 之后的 GitHub Pages 部署才是自动的。

## 一、以后可以直接这样发起任务

### 直接制作并发布

复制以下文字，替换方括号内容即可。论文 slug 是用于网址的简短英文名称，例如 `pi-zero`。

```text
请使用 paper-deep-reader，详细解读这篇论文并发布到我的「观行」网站。

论文：[官方论文链接或 PDF]
补充材料：[如有，提供附录、技术报告或官方代码链接]
重点：[例如数据、模型结构、训练方法、算力与基础设施]
文章 slug：[英文小写、数字和连字符，例如 pi-zero]

网站仓库：https://github.com/jianqiang03/jianqiang03.github.io
先检查现有本地仓库和远程状态，保留其他未提交修改。

要求：
1. 阅读原文和相关补充材料；明确论文版本、原文来源与证据边界。
2. 用六部分组织解读，讲清关键公式和一个贯穿方法的具体例子。
3. 逐张核验关键图表；解释读图方法、观察、推理和局限。
4. 保留 report.md、source_map.json 和 visual_manifest.json 等工作材料。
5. 在 notes/<slug>/index.html 创建文章，沿用现有论文页的居中布局、
   移动端目录、图表放大和返回主页功能，替换所有旧论文内容。
6. 在首页新增文章入口并更新笔记数量，保留已有 Dyna-2 解读。
7. 检查内容、图片、相对链接、手机与桌面排版。
8. 将本次站点文件提交并推送到 main，等待部署并检查线上页面。
9. 返回文章网址、改动文件和仍未确认的事实；不得编造缺失信息。
```

如果只想先看效果，把第 8 条替换为：

```text
只完成本地预览，不提交、不推送。交付预览文件和核验结果，等我确认后再发布。
```

未提供 slug 时，可以让 AI 根据论文名称取一个；没有公开的超参数、训练成本或数据来源时，应明确写“原文未披露”，不要猜一个数字填空。

## 二、先准备哪些信息

| 信息 | 用途 | 是否必需 |
| --- | --- | --- |
| 官方论文链接、arXiv 页面或 PDF | 确定原文与版本 | 必需 |
| 阅读重点 | 分配解释篇幅，避免只写摘要 | 建议 |
| 附录、技术报告、官方代码 | 补足配置和实现证据 | 有则提供 |
| slug | 决定目录与网址 | 可由 AI 拟定 |
| 发布方式 | 直接发布或只做预览 | 明确选择 |

只有标题时先定位原文，不能根据标题直接生成详细解读。论文修改过版本时记录具体版本；主文、附录和代码来自不同版本时说明差异。

## 三、确认在哪个目录工作

本机此前创建的发布仓库位于：

```text
/home/woan/Xiaomi-Robotics-1/outputs/personal-site/publish
```

这是带 `.git`、关联远程仓库的目录。`outputs/personal-site/site` 是之前的本地预览副本，**只修改那里不会自动更新发布仓库**。日常维护以 `publish` 或你另行克隆的仓库为准。

在另一台机器上可以重新克隆：

```bash
git clone https://github.com/jianqiang03/jianqiang03.github.io.git
cd jianqiang03.github.io
```

开始修改前检查：

```bash
git status --short
git remote -v
git branch --show-current
```

确认目标是本站仓库和 `main` 分支。工作区干净时，可以用 `git pull --ff-only` 更新。发现其他未提交修改时先识别归属，不能直接覆盖、清理或混进本次提交。

## 四、分开保存阅读工作材料与网站成品

建议采用两套目录。阅读工作区放在网站仓库之外，公开站点只放实际需要发布的文件。

```text
阅读工作区：<slug>-deep-read/
├── report.md                 # 经核验的正文，可继续修改
├── source_map.json           # 主张、来源位置、证据强度与局限
└── assets/
    ├── visual_manifest.json  # 图表清单与核验记录
    ├── crops/                # 核验后的图表
    ├── pages/                # 阅读用页面渲染
    └── text/                 # 提取文本等工作资料

网站仓库：jianqiang03.github.io/
├── index.html                # 新增首页入口
└── notes/<slug>/
    ├── index.html            # 发布的文章
    └── assets/               # 若采用外部图片，放实际引用的图表
```

当前 Dyna-2 是图片内嵌的单文件 HTML。新文章既可采用同样方式，也可使用 `assets/` 图片文件；后者更方便维护和单独缓存。不要把整个下载目录或原始 PDF 默认放进公开站点；需要公开的素材应检查来源和使用条件。

## 五、深读不是翻译摘要：按这条证据链写

默认使用 `paper-deep-reader` 的六部分结构：

| 部分 | 必须回答的问题 |
| --- | --- |
| 1. 核心思想一句话总结 | 最核心的技术主张是什么？ |
| 2. 背景与动机 | 原有方法为什么不够？需要理解哪些概念？ |
| 3. 核心方法/模型 | 输入、模块、中间状态、输出如何连接？公式每项起什么作用？ |
| 4. 实验与结果 | 哪个实验验证哪个主张？对照是否公平？数字代表什么？ |
| 5. 贡献与影响 | 真正新增了什么？代价是什么？下一步如何最小验证？ |
| 6. 结论 | 哪些结论可信、适用到哪里、是否值得进一步复现？ |

方法部分至少用一个具体例子走完输入到输出；简单数值例子要标为说明用例，不得写成作者的实验结果。训练超参数、数据小时数、模型规模和硬件信息分别追溯来源，不能从多个不同版本拼成一套“完整配置”。

实验解读应区分成功率、归一化得分、相对提升和百分点；区分单模块耗时与端到端速度；区分离线指标与真实闭环执行。

### 每张关键图都按同一顺序讲清楚

1. 图前：这个图回答什么问题，先看哪条轴或哪个面板？
2. 图本身：嵌入核验过的图片，保留完整坐标轴、图例、单位和误差范围。
3. 图后：观察到了什么，为什么支持某条结论？
4. 边界：它不能证明什么，还有什么替代解释？
5. 来源：标明原文图号、章节或页码，附原文链接。

不要为了凑数量收录图表，也不要遗漏承载核心结论的图。裁图应去掉无关空白，但不能裁掉图例或关键面板。没有视觉核验条件时明确说明限制，不能声称已经看过图中的曲线或颜色。

### 可选的技能检查

在已安装该技能的本机环境中，可执行以下命令。`PAPER_OUTPUT` 改为实际阅读工作区，技能安装路径不同则修改 `SKILL_DIR`。

```bash
SKILL_DIR="$HOME/.codex/skills/paper-deep-reader"
PAPER_OUTPUT="/absolute/path/to/paper-deep-read"
python3 "$SKILL_DIR/scripts/validate_report.py" "$PAPER_OUTPUT/report.md" \
  --mode explain \
  --manifest "$PAPER_OUTPUT/assets/visual_manifest.json" \
  --source-map "$PAPER_OUTPUT/source_map.json" \
  --strict
```

清单结构应按技能自带模板建立，不要为了让检查通过伪造核验状态。此检查验证结构、资产引用和解读要素，不会自动证明事实正确，也不会把 Markdown 自动转换成网页。HTML 仍需制作和浏览器检查。

## 六、制作新的 HTML 文章

以 `notes/<slug>/index.html` 为入口，对外网址为：

```text
https://jianqiang03.github.io/notes/<slug>/
```

可以借用 Dyna-2 页的布局代码，但它目前是一个成品页面，并不是会自动替换变量的空模板。复制后必须逐项更换：

- `<title>`、主标题、侧栏标题和文章简介。
- 全部正文、图表、图注、来源、数字和结论。
- 目录链接与对应的章节 `id`；二者保持匹配。
- 图片 `alt`、实际图片路径及真实宽高。
- 页脚说明和特定于 Dyna-2 的文字。

保留通用交互：目录跳转、返回主页、图片点击放大、Esc 关闭、键盘操作。文章位于两级目录下，返回主页链接用 `../../`；图片路径例如 `assets/figure-1.png`。

排版沿用当前修正方案：桌面为左侧目录加剩余空间居中的阅读区；文字行长适中，图表可以更宽；手机把侧栏变成顶部目录。不要重新使用单独的固定 `margin-left` 将正文锁在左侧。详细原理见[建站教程的论文排版章节](github-pages-guide.md#7-论文页怎么做以及为什么曾经偏左)。

若使用外部图片，示例是：

```html
<img src="assets/figure-1.png"
     alt="图1：模型的输入与动作输出路径"
     width="1200" height="800" loading="lazy">
```

宽高必须换成该图片真实尺寸，CSS 再用 `max-width: 100%; height: auto;` 适配视口。不能只改文字而留下旧的 Base64 图片。

## 七、接入首页：当前需要手动新增入口

根目录 `index.html` 中，找到 `id="notes"` 的区域。现在只有一个指向 `notes/dyna-2/` 的 `.featured` 卡片。新增文章时保留它，再添加一张卡片；首页不会自动扫描 `notes/`。

以下示例沿用现有 CSS 类，放在已有 `.featured` 卡片后、`notes` 区域的 `</section>` 前。把示例标题、slug、摘要、标签全部替换成真实内容：

```html
<a class="featured" href="notes/your-paper/">
  <div class="feature-art">
    <span class="art-label">PAPER / DEEP DIVE</span>
    <strong>PAPER</strong>
    <span class="art-bottom">METHOD → EVIDENCE</span>
  </div>
  <div class="feature-copy">
    <p class="eyebrow">论文深读 · 研究主题</p>
    <h3>这篇论文解决了什么具体问题？</h3>
    <p>用两句话说明技术主线，以及这篇解读最值得看的部分。</p>
    <div class="tags"><span>模型方法</span><span>实验分析</span></div>
    <div class="read-link">阅读全文 <span>↗</span></div>
  </div>
</a>
```

如果使用多张连续卡片，在 `style.css` 增加一次间距规则：

```css
.featured + .featured { margin-top: 24px; }
```

再把 `.count` 中的 `01 篇笔记` 更新为真实数量，例如 `02 篇笔记`。长英文封面标题应缩短或调整字号，避免在手机上超出边界。文章很多时再改为列表或内容索引，无需现在引入复杂框架。

## 八、本地检查：内容、页面、入口都要通过

在发布仓库根目录运行：

```bash
python -m http.server 8080 --bind 127.0.0.1
```

在同一台电脑上打开 `http://localhost:8080/`，从首页点击新文章。远程开发时先转发该端口。不要只用双击 HTML 的方式判断目录链接是否正常。

发布前逐项确认：

- [ ] 标题、论文版本和原文链接正确，没有旧论文残留。
- [ ] 每项关键数字能回到来源；推断与作者结论分开标记。
- [ ] 所有关键图可读，无裁断图例、失效路径或不明空白。
- [ ] 首页新入口、旧入口和文章返回主页都可用。
- [ ] 首页文章数量正确，目录跳到对应章节。
- [ ] 手机 390px、平板 768px、桌面 1440px 和大屏 1920px 没有整页横向溢出。
- [ ] 宽表格可以在自己的区域滚动，不撑开整个页面。
- [ ] 图片放大、关闭及 Esc 操作正常，懒加载时不明显跳动。
- [ ] 新文章没有隐藏的草稿占位、编造内容或不应公开的本地资料。

图片数量、字数或验证脚本“通过”，都不能替代实际检查内容与渲染。

## 九、只提交本次文章相关文件，然后发布

先检查差异：

```bash
git status --short
git diff --check
git diff --stat
```

以下示例将 `your-paper` 替换为实际 slug。在首页和样式确实发生相关修改时，一起提交：

```bash
git add notes/your-paper/index.html index.html
# 如果使用了外部图片，再执行：
git add notes/your-paper/assets
# 如果为了新增卡片修改了样式，再执行：
git add style.css

git diff --cached --stat
git commit -m "Add deep reading of your-paper"
git push origin main
```

不存在的目录无需暂存。避免直接 `git add .` 把其他工作内容一并发布。如果要求先预览，就停在本地交付，不运行这段提交和推送步骤。

本站已经配置 GitHub Pages，无需为每篇文章重新建仓库或重新开启 Pages。推送后在仓库 Actions 中等待对应提交的 `pages-build-deployment` 完成。也可以查看：

```bash
gh run list --repo jianqiang03/jianqiang03.github.io --limit 3
```

完成后验证首页与新文章的正式网址，并确认线上显示的是最新内容。如果显示旧页面，先核对对应提交是否部署成功，再尝试强制刷新，不能仅凭推送成功就宣布上线完成。

## 十、以后修改或撤回文章

修改正文：现有三篇以 `notes/<slug>/report.md` 为正文源文件，修改后运行 `python scripts/render-paper-note.py <slug>` 生成 HTML（依赖 `markdown`、`beautifulsoup4`）。同步更新同目录 `source_map.json` 中受影响的证据。渲染器保留当前页面外壳、共享样式和图片放大功能；不自动部署。新文章仍需先建立 HTML 外壳并在脚本中登记重点导航。若改了标题或摘要，同步首页卡片。调整图片时同步图注、alt 和宽高。保留必要的更正说明，不要悄悄让旧实验数据看起来像新结果。

修改网址会使旧链接失效，因此尽量在首次发布时确定 slug。发现已发布版本有问题时，可对特定提交执行 `git revert <commit>` 后正常推送；先检查该提交还改了什么，避免连带撤回无关内容。

最终交付应包含：**线上文章地址、首页入口、对应 Git 提交、核验结果、仍有局限的内容，以及阅读工作材料的本地位置。** 这样下一次修改能继续追溯，不必从头读起。


### 阅读页的排版约定

所有文章在内联样式后加载 `../reading.css`。共享样式采用统一阅读宽度：桌面正文、标题、图表和表格上限均为 900px；正文 18px，行距 1.85，侧目录 208px。手机端使用 16px 正文与 20px 留白。所有内容左右对齐，不让正文随屏幕无限加宽。表格使用 `.table-scroll` 外层负责滚动，内部 `table` 保持 `display: table; width: 100%`，避免可见单元格未铺满容器。

本轮依据 [Taste Skill](https://github.com/leonxlnx/taste-skill) 的字体、布局和截图复查流程调整阅读组件，保留既有研究文章、原图与跳转。其宣传站检查项（大幅主视觉、动画数量、首屏按钮）不作为学术长文的发布条件；文章不增加与阅读无关的装饰内容。

修改后在 390、768、1440、1920px 检查正文、原图、表格、公式和目录，并验证图片放大与键盘关闭。三篇页首提供实现重点导航，与正文使用相同阅读边界。

共享 CSS 的 URL 应带内容哈希版本，例如 `../reading.css?v=<sha256前12位>`。更新样式时同步更新所有文章的引用，避免 GitHub Pages 的十分钟浏览器缓存让修改暂时不可见；生成脚本会自动计算版本。

配色使用 `reading.css` 顶部的 CSS 变量统一维护：白色阅读底、深蓝灰标题与正文、蓝绿色链接、浅蓝灰目录；表格以深色表头和浅色隔行区分。保持正文/图表 900px 的统一边界；不要独立覆盖表格容器宽度。

### 实现深读的内容标准

模型类解读沿一条样本讲清数据切片、张量与掩码、目标与损失归约、梯度流向和推理执行。每项核心设计解释如何改变信息、监督或优化，列出成立条件、失败情况与可区分的证据。官方代码固定到 commit，标明预训练、微调或推理阶段；公开微调实现不能补造未公开预训练细节。教学伪代码、本文推断和未披露项必须明确标注。

现有三篇可一起渲染：

```bash
python scripts/render-paper-note.py dyna-2 vpp2 dm05
```

同时提交正文、证据映射、生成的 HTML 和新增图片。外部旧版生成器只作为历史工作材料，仓库中的 Markdown 与此渲染器是后续维护入口。
