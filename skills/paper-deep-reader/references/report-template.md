# 机制驱动的报告模板

此文件与 SKILL.md 定义本地默认写法。六部分是网站兼容外框，正文小节按论文的决定性问题命名；不按下列提示逐项生成固定标签。

## 1. 核心思想一句话总结

标题下给论文版本和一手来源链接。用不超过 50 字的一句话说清核心问题与改动，再用短段点出最重要的证据和阅读主线。详细来源账本放 source_map。

## 2. 论文背景与动机

从一个具体样本或失败场景开始，指出已有做法为什么留下歧义，紧接着给作者的解决方向。必要术语随场景解释。只介绍影响理解该改动的相邻工作，不先铺一整段领域史。

## 3. 核心方法/模型详解

先画出输入到输出的路径，用一条样本说明各模块角色。之后用问题作为小节标题，每节讲完作者操作、计算机制和训练到推理的衔接。模型类论文通常需要覆盖：

- 数据如何构造：来源、切分、标签、时间对齐、采样与有效样本定义。
- 条件和表示如何进入模型：实际输入、编码、张量/掩码与信息访问范围。
- 怎么训练：目标、损失归约、梯度路径、冻结与更新、阶段衔接。
- 怎么使用：部署条件来源、生成与执行时钟、更新与延迟处理。

这些是覆盖检查，不要求生成四个同名小节。正文可将一个模块的训练和推理相邻讲完。公式、伪代码与附录参数在解释该操作时出现；教学伪代码标为示意，缺失细节不补造。基础设施说明具体解决什么瓶颈，速度附硬件、精度、负载与测量范围。

图表放在它承担论证的位置。图前交代关注的比较，图后用连续自然段解释观察和支持范围，不套六个标签。多图共用同一论点可连贯讨论，但不能遗漏关键对象的含义。

## 4. 实验与结果分析

按待验证问题命名小节：系统收益、核心改动消融、泛化范围、成本与失败等，按论文证据选择。先说比较控制了什么、指标测什么，再报关键数字，最后解释其对方法假设的支持。未隔离的变量影响结论时明确说明。

不要把结果的合理机制解释写成作者证明的因果结论。把实验条件和模块对应起来，让读者知道为什么需要下一项实验。

## 5. 论文的贡献与影响

指出可以迁移的具体机制、需要的前提以及一项有根据的缺口。若用户关心自己的训练，区分作者方法和建议方案，给最小区分实验；不添加泛泛的未来方向清单，不重复摘要。

## 6. 结论

简短收束：最值得借鉴的改动、最可信的证据、最大的未解决点。读者应知道下一步值得检查或实现什么。

## 其他模式

`brief` 与 `targeted` 不强制六部分；只回答所需范围。`audit` 在主文外补充必要账本或复现材料，避免重复正文。

## 原创示例：怎样把问题讲完

下面是用于检查解释质量的抽象教学例，不是任何指定论文的复现配方：

同一任务的两条轨迹分别包含平稳搬运与抓取后的反复调整。只有任务文字时，两类动作共享同一条件，模型需要在未解释的行为差异中拟合输出。若方法为轨迹增加行为标签，标签作为输入改变了条件分布；动作监督仍来自各自轨迹，并没有自动删除较差样本的损失。部署时选择期望的标签，才能请求相应行为。这个解释成立还需要标签可靠、条件可辨识且训练中有足够覆盖。是否确实有效，应查看同一数据与预算下有无标签的对照；仅展示最终系统成功率不足以隔离标签的作用。

实际论文解读应把上述抽象操作替换为可定位的作者方案、标签来源、条件用法和实验数字。作者未披露的部分明确留下缺口，不将这个例子套成事实。
